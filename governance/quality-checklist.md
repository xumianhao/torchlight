# 发布前质量清单

写入或更新正式知识前，按内容类型完成适用检查。未通过项应说明限制、降级主张或登记待验证。

## 通用检查

- [ ] 证据仅覆盖国服，未将国际服资料用于国服结论。
- [ ] 已披露联网、离线或无法核验的条件与限制。
- [ ] 服务器、赛季、创建日期、核验日期、状态、可信度和复核触发条件元数据完整。
- [ ] 每项关键主张可追溯至具体来源记录。
- [ ] 已区分事实、实测、模拟与推断。
- [ ] 已处理冲突，或已保留冲突证据并登记冲突日志。
- [ ] 外部链接和内部链接可定位、有效。
- [ ] 未解决主张已降级表述或登记为待验证，而非写成确定事实。

## BD 检查

- [ ] 明确目标受众。
- [ ] 明确适用进度阶段。
- [ ] 明确预算层级与条件。
- [ ] 明确用途。
- [ ] 说明适用难度或挑战边界。
- [ ] 写明核心条件。
- [ ] 提供替代方案或说明无替代的条件。
- [ ] 包含进度与成长路径。
- [ ] 说明进攻逻辑或验证边界。
- [ ] 说明防御逻辑或验证边界。
- [ ] 说明资源循环或验证边界。
- [ ] 说明操作要求。
- [ ] 列出失败案例或不适用情形。
- [ ] 说明测试条件、测试限度或缺失测试。
- [ ] 列出可追溯来源。

## 策略检查

- [ ] 明确问题范围。
- [ ] 说明前置条件。
- [ ] 给出可执行步骤。
- [ ] 说明成本。
- [ ] 说明预期回报及其证据边界。
- [ ] 说明风险。
- [ ] 说明时间投入。
- [ ] 说明分支或条件变化时的处理方式。
- [ ] 说明退出或停止条件。
- [ ] 列出常见错误。
- [ ] 说明样本、样本限制或缺失样本。
- [ ] 列出可追溯来源。

## 问答检查

- [ ] 先给出直接答案。
- [ ] 写明答案成立的条件。
- [ ] 写明例外或不适用情形。
- [ ] 标明适用国服赛季。
- [ ] 关联可追溯证据。
- [ ] 链接对应攻略或知识文档。
- [ ] 写明重新核验触发条件。

## 维护检查

- [ ] 确认资料应写入的目标位置。
- [ ] 完成重复内容检测。
- [ ] 检查受影响的内部和外部链接。
- [ ] 按政策完成内容状态迁移。
- [ ] 保留历史、来源和失效脉络。
- [ ] 按需更新冲突登记表。

约束规则：任何关键检查失败都会阻止将相关主张写为确定性结论；但可将证据或问题记录为待验证事项。
