# 《火炬之光：无限》国服攻略知识库设计

## 1. 项目目标

本项目建立一套供 AI Agent 长期维护的《火炬之光：无限》国服攻略知识库。Agent 同时承担以下任务：

1. 搜集、核验并撰写 BD 攻略和策略攻略；
2. 维护结构化、可追溯、可跨赛季演进的知识库；
3. 基于已核验资料回答玩家问题。

本阶段只建立根级规范、基础目录和内容模板，不研究或填充当前赛季的真实攻略内容。

## 2. 范围与语言

- 游戏范围：仅《火炬之光：无限》国服。
- 时间范围：长期维护，覆盖当前及后续赛季。
- 玩家范围：新手、普通玩家、进阶玩家和极限玩家。
- 内容范围：全部 BD 类型及全部策略主题。
- 来源范围：国服官方、国服社区、国服视频与直播、数据库、模拟器和用户提供的信息。
- 排除范围：国际服资料不得作为国服事实的来源、佐证或替代证据。
- 正文语言：简体中文。
- 路径命名：使用稳定的英文名称。
- 游戏术语：优先使用国服官方名称，可以附常见别名。

## 3. 质量优先级

项目按以下顺序处理质量目标；发生冲突时，高优先级目标优先：

1. 阻止国际服资料和过时信息混入国服知识；
2. 防止编造数值、机制或无依据结论；
3. 确保 BD 可以按预算和阶段实际落地；
4. 保证知识结构适合长期维护；
5. 统一不同 Agent 的输出结构与质量。

信息正确性高于内容完整度。资料不足时，Agent 必须明确标记不确定性或登记待验证问题，不得补猜以制造完整答案。

## 4. 总体架构

采用“稳定知识 + 赛季知识”双层结构：

```text
/
├─ AGENTS.md
├─ README.md
├─ knowledge/
│  ├─ core/
│  │  └─ README.md
│  ├─ seasons/
│  │  └─ README.md
│  └─ qa/
│     └─ README.md
├─ templates/
│  ├─ build-guide.md
│  ├─ strategy-guide.md
│  ├─ qa-entry.md
│  ├─ source-record.md
│  └─ verification-record.md
├─ governance/
│  ├─ taxonomy.md
│  ├─ source-policy.md
│  ├─ freshness-policy.md
│  ├─ quality-checklist.md
│  ├─ pending-verification.md
│  └─ conflict-log.md
└─ archive/
   └─ README.md
```

### 4.1 文件职责

- `AGENTS.md`：Agent 的最高执行规范，定义范围、优先级、工作流、禁止事项、写入规则和完成标准。
- `README.md`：面向维护者介绍仓库用途、入口和基本使用方式，不重复整份 Agent 规范。
- `knowledge/core/`：保存不绑定单一赛季的稳定国服知识；稳定知识仍需记录最后核验日期。
- `knowledge/seasons/`：按赛季隔离时效内容。实际创建赛季时，在赛季目录内至少区分 `builds/` 与 `strategies/`。
- `knowledge/qa/`：从已核验资料中沉淀可复用问答，不允许成为无来源结论的独立存放区。
- `templates/`：规定各类内容的结构、元数据和必填字段。
- `governance/`：保存详细分类、来源、时效、质量、待验证和冲突处理规则。
- `archive/`：保存已失效的历史内容及其脉络，避免删除后失去追踪依据。

## 5. Agent 工作流

Agent 接到任务后按以下顺序执行：

1. **识别任务类型**：判断任务属于 BD 攻略、策略攻略、知识维护、玩家问答或复合任务。
2. **确定适用范围**：明确国服、目标赛季、玩家阶段、预算、用途和任务所需的新鲜度。
3. **检查联网状态**：联网 Agent 可以检索、核验并新增时效信息；离线 Agent 只能整理仓库已有材料，不得声称已经核验当前版本。
4. **检索已有知识**：优先复用仓库内容，并检查赛季、更新时间、可信度和过期状态。
5. **研究国服来源**：优先采用官方资料，以国服实测、社区资料、视频、直播、数据库和模拟器作为补充。
6. **分类事实状态**：区分已确认事实、社区实测、合理推断、存在争议和待验证内容。
7. **写入正式知识库**：按内容性质写入稳定知识、指定赛季或问答目录；无法确认归属或事实状态时，登记到待验证清单。
8. **执行发布前自检**：核对国服来源、赛季、日期、模板字段、数值依据、冲突、失效风险和证据可追溯性。

项目不设置人工草稿审核门槛。Agent 可以直接修改正式知识库，但必须先通过自动自检规则。

## 6. 硬性边界

Agent 不得：

- 引用、翻译或改写国际服资料作为国服依据；
- 因名称相同而假定国际服与国服机制一致；
- 编造来源、数值、掉率、伤害、价格或机制；
- 将旧赛季结论无标记地沿用到新赛季；
- 将模拟结果表述为游戏内实测；
- 为了内容完整而补全证据不足的结论；
- 仅依据搜索摘要或无法回溯的二手转述写入关键事实；
- 删除冲突证据而不保留决策记录；
- 将市场价格写成无日期、赛季和样本条件的长期固定值；
- 在玩家问答中降低来源和时效标准。

## 7. 分类体系

### 7.1 BD 分类维度

- 英雄与英雄特性；
- 核心技能与流派；
- 开荒、过渡、成型和极限阶段；
- 低、中、高和极限预算；
- 刷图、攻坚、生存和速刷等用途；
- 当前可用、条件可用、待复核和已过期状态。

### 7.2 策略主题

- 赛季开荒；
- 职业与流派选择；
- 装备与打造；
- 天赋、技能与养成；
- 通货与资源规划；
- 交易市场；
- 异界推进与刷图路线；
- 首领与玩法机制；
- 赛季机制与活动；
- 收益、效率与风险分析；
- 账号长期养成；
- 工具、数据库与模拟方法。

分类体系允许后续扩展，不在根级规范中写死未来赛季的新玩法。

## 8. 内容模板

### 8.1 BD 攻略必填内容

- 标题和一句话定位；
- 国服赛季、最后核验日期、内容状态和可信度；
- 适用玩家、阶段、预算、用途和操作难度；
- 核心机制及成立条件；
- 英雄、特性、技能、辅助技能和天赋；
- 核心装备与关键词条；
- 平价替代和不可替代项；
- 从开荒到成型的升级路线；
- 输出、防御、资源循环和操作方式；
- 优点、缺点、失败条件和不适用场景；
- 测试条件、已知争议和待验证项；
- 来源记录。

缺少真实验证时，不得给出精确伤害上限或宣称“毕业强度”。

### 8.2 策略攻略必填内容

- 问题、目标与适用范围；
- 国服赛季、最后核验日期、内容状态和可信度；
- 前置条件；
- 分步执行方法；
- 成本、收益、风险和时间投入；
- 不同预算或阶段的分支方案；
- 停止、切换或退出策略的条件；
- 常见错误与纠正方式；
- 数据样本、假设和局限；
- 来源和待验证项。

### 8.3 问答条目必填内容

- 标准问题和常见问法；
- 简短结论；
- 条件化详细回答；
- 适用赛季、玩家阶段和例外情况；
- 可信度、最后核验日期和来源；
- 关联的 BD 或策略文档；
- 触发重新核验的条件。

### 8.4 来源记录

来源记录必须足以让后续维护者重新定位证据，至少包含标题或描述、来源类型、发布者、发布日期或获取日期、链接或定位方式、适用赛季、支持的结论、测试条件和来源等级。

### 8.5 验证记录

验证记录至少包含待验证命题、验证方法、环境和条件、原始结果、结论、执行日期、执行者或来源、关联文档及未解决问题。

## 9. 来源与可信度治理

### 9.1 来源等级

- `S`：国服官方，包括官网公告、更新说明、游戏内文本和官方发布内容。
- `A`：可复现的国服实测，明确展示版本、条件、过程和结果。
- `B`：可信的国服社区经验，作者与上下文明确，但测试过程不完整。
- `C`：用户陈述、零散讨论、搜索摘要或无法完整回溯的二手线索。此级别不能独立支撑关键结论。

第三方数据库和模拟器不固定归级，应根据数据来源、版本匹配度及可复现性判断，并明确标注数据性质。

### 9.2 可信度状态

- `confirmed`：官方确认，或被可靠实测重复验证；
- `supported`：有较强国服证据，但尚未完全确认；
- `tentative`：合理推断或仅有单一来源；
- `disputed`：可靠来源之间存在冲突；
- `unverified`：尚无足够证据。

`tentative`、`disputed` 和 `unverified` 内容不得使用确定语气。

## 10. 时效治理

每篇正式内容必须记录：

- 适用服务器，固定为国服；
- 首次创建日期；
- 最后核验日期；
- 适用赛季；
- 内容状态；
- 触发重新核验的条件。

内容状态包括：

- `current`：已对目标赛季完成核验；
- `needs-review`：因新赛季、补丁或机制变化需要复核；
- `partially-outdated`：部分仍有效，部分已失效；
- `archived`：不再适用于当前赛季；
- `unknown`：无法确认当前有效性。

新赛季上线或相关补丁发布后，旧结论不得自动继承。受影响文档应先转为 `needs-review`，完成国服核验后才能恢复为 `current`。

## 11. 冲突处理

发现来源冲突时：

1. 保留各方证据，不覆盖或删除旧证据；
2. 记录来源、测试条件、赛季和日期；
3. 检查冲突是否来自赛季、环境、装备条件或样本差异；
4. 优先采用国服官方和可复现证据；
5. 无法解决时将结论标记为 `disputed`；
6. 将所需补测登记到 `governance/pending-verification.md`；
7. 在 `governance/conflict-log.md` 中记录采用结论及理由。

## 12. 自动质量门槛

Agent 直接写入正式知识库前必须确认：

- 未使用国际服来源；
- 服务器、赛季、日期和状态元数据完整；
- 关键数值可以追溯到证据；
- 事实、实测、模拟、推断和争议明确分离；
- 对应模板的必填内容完整；
- 来源描述足以重新定位证据；
- 与已有文档的冲突已经处理；
- 不受支持的结论已经降级表述或登记为待验证项；
- 内部链接和关联文档路径有效。

任一关键门槛未通过时，Agent 不得将相关结论写成确定事实。

## 13. 验收标准

实施完成后，应验证：

1. 所有约定文件存在且内部链接有效；
2. `AGENTS.md` 能独立说明最重要的强制规则；
3. 模板字段与治理规范使用一致的名称和枚举；
4. BD、策略、知识维护和玩家问答四种任务都有明确流程；
5. 国际服来源、旧赛季结论和证据不足三类风险都有阻断规则；
6. 联网与离线 Agent 的权限边界一致且无矛盾；
7. 仓库不包含未经研究的当前赛季事实；
8. 文档中的未决事项均已处理，且不存在含义不明确的规则。

## 14. 实施边界

本设计对应一次聚焦的仓库脚手架实施：创建 `AGENTS.md`、说明文档、基础目录、治理文档和空内容模板。首批真实 BD、策略攻略、问答条目以及当前赛季研究属于后续独立任务。
